# 本地 Demo 已知限制

本项目用于本机完整演示和测试，不等同于生产环境部署。当前边界如下：

- 花名册只实现本地 Excel 读取；`OaViewRosterSource` 是第二阶段只读 OA 适配器占位，不包含 OA 地址、账号、IP 或数据库连接。
- SQLite 适合单机演示，不适合多人并发、集群部署或高可用场景。
- 私有文件通过登录态接口读取并禁止公开静态目录直链，但本机管理员仍可直接访问磁盘文件；生产环境需要对象存储、细粒度授权、密钥管理和备份策略。
- “学习催办”邮件仍只写入 `SIMULATED_NO_SMTP` 日志，不发送真实邮件，也不连接企业微信、Teams 或短信服务。员工“找回密码”和“入职欢迎邮件”是独立 SMTP 通道；找回密码未配置 SMTP 时仅开发环境提供明确标记的模拟链接，欢迎邮件自动化与运行时投递均默认关闭。
- 入职欢迎邮件使用本机定时 worker；休眠、关机或 worker 未运行时无法按时发送，只会按配置的 1–7 天回看窗口补建。系统记录 SMTP 接受、失败和未知状态，但没有真实邮件服务商的投递回执、退信 webhook、打开率或点击率。
- 入职欢迎邮件附件缓存的 64 MiB 只限制单轮保留的已校验附件，不是进程峰值内存上限；还需计入一封正在校验的最多 20 MiB 原始附件、Nodemailer 流式编码和 Node.js 运行时开销。25 MiB MIME 上限包含 1 MiB 传输头安全余量。
- macOS LaunchAgent 脚本只生成 plist，不会自动加载、卸载或创建系统级守护进程；Windows 定时任务尚未提供安装脚本。
- 入职资料包会校验允许的扩展名、MIME、魔数和 Office 容器结构，并拒绝宏、ActiveX 与压缩炸弹，但本地 Demo 不包含商业杀毒、内容沙箱或 DLP 扫描。生产使用前仍需接入恶意文件检测。
- 员工端板块权限是全局开关，不支持按部门、岗位、城市或单个员工分别配置。
- 制度 PDF 由管理员在本地上传。仓库不包含公司的真实制度文件，避免误提交敏感资料。
- 城市指南使用工作目录中现有源文件渲染出的 16 页本地图片；更新 PPTX/PDF 后需要重新渲染并运行 `pnpm guides:import`。
- Demo 已实现邮箱密码找回、请求限流和一次性令牌，但未实现单点登录、多因素认证、验证码、集中式恶意流量防护、集中日志和生产级密钥轮换。
- 浏览记录以打开已发布制度文件为准，不代表完成逐页阅读或电子签收。
- 响应式验收覆盖主流程和规定尺寸；非常旧的浏览器与 Windows 高对比度之外的特殊辅助模式未做完整兼容认证。

第二阶段接入真实 OA 前，应先确定只读视图字段、更新频率、网络白名单、数据脱敏、失败回退和审计责任，再替换 `RosterSource` 的实现，业务服务和页面无需直接依赖 OA。
